## 对照边界

这是单变量模拟“没有新增验收”的路径，不是把整个仓库回滚到历史版本：两组均保留当前8轮上限、当前严格兼容性规则和其余修复。既有 Jev 路由/工具选择实验在两组都关闭。总计时覆盖 `runConversation` 从入口模型调用到最终回答返回，包括工具、候选生成、验收与必要修正；不含进程启动，不测浏览器传输或真实 MySQL 延迟。

off 不具备新增的独立语义验收保障，两组做的检查不同；不得把少做检查的耗时优势说成同等正确性的优化。合成目录中候选本身符合语义要求，并为兼容性提供明确合成证据；不代表真实商品规格已核验。

## 结论

这次没有证明新增Jev验收能加速整个Agent。唯一两边均成功的语义配对中，开启后总耗时更长，Jev增加一次546ms请求，主模型调用没有减少。新增节点承担额外核验职责；降低节点内部请求次数不等于比没有该节点更快。当前入口规划反复失败的独立问题干扰完整流程的性能对照，不能凭这些小样本确定稳定增幅或将失败归因给Jev。未为通过测试修改入口、Planner或超时上限。
