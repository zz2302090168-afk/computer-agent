# 本轮多意图计划与执行

## 全量目录分页完成校验

目录节点用 `catalogScope=all` 表达用户明确要求查全；普通单页/前几条使用 `page`。用户指定每页上限时由入口记录 `catalogPageSize`。范围识别来自入口模型结构化结果，不使用助手文本或关键词正则作为完成依据；兼容旧计划时字段仍可省略，因此本机制不能证明入口永不漏提要求。

全量查询从 offset=0 开始，执行前校验计划/首查询的筛选条件、limit 和当前 nextOffset。每项节点单独记录实际成功返回的连续页面、商品 ID、总数及下一页；只有末页返回 null 且去重商品数量等于匹配总数时才满足全量完成条件。跳页、重复页、变更过滤/排序/limit、失败结果不能冒充完整覆盖。普通单页不要求翻到末页。查询过程中目录数量发生变化时不宣称已查全；没有新增快照持久化、自动重启查询、重试或额度。

模型提前输出结束文本会被既有未完成校验拦截；继续查询仍有机会完成，原有修正额度耗尽则报告未完成。最终自然语言是否逐项列全商品仍需另行检查，程序覆盖校验不等同于完整文本质量审核。

2026-09-20 修复复测：初版只有结果侧校验，真实模型五次仅一次通过，随后补充诊断确认一次请求添加 maxPrice=0、limit=10 后以空结果结束。最终版同时补充入口参数说明和执行前范围门禁，使用同一分页请求完成新一组五次复测，全部满足八张显卡覆盖、每页最多两条、任务完成、无需求写入。模型调用数依次为 6、5、5、5、5；本轮为正确性复测，期间还运行了开发检查，不作为性能对照。原50次性能数据不重写。

验证：268项回归测试通过，新增覆盖提前结束后的继续/阻断、普通单页、跳页、重复、筛选变更、每页上限、失败、空目录和节点隔离；类型检查、相关代码检查、构建通过。真实模型使用测试目录，未执行业务数据库与页面端到端复测。

入口仍为 `set_request_action`，公开格式只有 `sourceMessageId` 和非空 `nodes`。第一次模型调用同时识别全部意图并规划任务：单意图也用一个节点，多意图使用 `task1`、`task2`、`task3` 和 `dependsOn`。每项含动作、目标、用户原文引用，可附 `invocation: {tool, arguments}` 和 `expected: {tool, arguments}`。不额外强制一次分类或Planner调用；复杂任务内部仍使用受限ReAct工具循环。旧单意图简写仅在入口兼容展开为task1，不再维护单独的执行路径。

程序校验节点ID、动作、引用、依赖存在性和无环性，并标记single、sequential、parallel或dag。调度前再次判断：依赖全部完成、主工具显式支持并行只读、参数及权限满足、没有共享写入冲突，才启动并行批次。当前允许目录查询、选择解释和换件候选查询，每批最多4项；参数不明确、依赖未完成、咨询附件首查询、写操作及未声明安全的工具走原串行路径，不跨越就绪写任务。shape只描述图结构，parallelDecision记录实际判断原因，parallelBatches记录已启动的批次。

并行分支使用隔离运行态和目录上下文，禁止状态保存或会话切换。只读观察按节点归属交回原有完成校验与收尾流程，不覆盖主draft/result/task；不能把一个查询的成功计为另一个查询完成。依赖任务等前置任务核验完成才运行。单支失败不丢弃其他分支结果，取消后不合并迟到结果，重规划会使旧批次缓存失效。DAG只用于同一条消息中的任务，不是多会话或持久化任务系统。

工具注册表为每项挂载元数据：适用任务、主工具映射、read/write/control副作用类别、失败时是否保留配置；参数Schema及执行器仍来自工具本身。程序将元数据与当前状态门禁相交。当前任务的主候选唯一、入口已给出完整合法参数且符合expected时，直接走原执行入口，不再调用Tool Selector。缺参数、需检索或有多个选择时继续模型工具循环，绝不因“只有一个工具”猜参数。没有可用主工具时交付NO_SUITABLE_TOOL，而不是开启新权限。前置参数检查只覆盖本项目Schema子集，业务审核始终不可省略。

每个节点从自己的工具事实起点核验完成情况，保留实际工具参数，不借用其他节点的成功记录。expected要求匹配成功工具调用的参数子集，需求保存和方案选定还核对当前状态；其他业务结果继续由已有工具审核保证。expected省略时使用invocation；两者均未提供时仍使用动作所需工具和已有业务完成条件。这不是任意自然语言目标的完备证明。

节点保留pending/running/completed/blocked调度状态，另用outcome区分成功、失败、等待用户与依赖阻断，并提供TOOL_FAILED、RESULT_MISMATCH、NO_SUITABLE_TOOL、DEPENDENCY_BLOCKED。失败节点阻断依赖项，独立节点继续，已成功写入的结果不回滚。全部完成后，在剩余模型额度内统一汇总；售后仍使用程序受控交付。含未完成节点时不拼接此前模型可能跨节点承诺成功的正文，按程序状态逐项说明。自然语言汇总仍需真实模型评测，不能声称完全消除幻觉。

复合任务遇到实际工具失败时，可使用revise_execution_plan进行一次受限重规划：仅改未完成节点的依赖和调用参数，不能增删意图、修改目标和原预期、重跑完成节点，不能更改操作权限。当前活动节点已有成功操作时不允许重规划，防止重放；普通参数纠正仍用原工具循环。重规划再次做完整DAG校验，不重置候选次数、失败去重或模型额度。

计划只存在当前请求内存，不写入数据库、不支持刷新恢复；诊断仍进入既有服务器日志。2026-09-23按用户需求验收任务的明确约定，将主循环由16次收紧到最多8次模型调用，保留原有两次未完成文本纠正及既有候选上限。直执行和并行只读批次不占模型调用次数，最终汇总计入8次；推荐分支原有内部模型调用另计。没有新增正则意图判定、并发写入或持久化checkpoint。节点内模型循环与收尾仍串行，这不是任意Agent任务的全并发执行。

并发回归使用受控Promise屏障证明两个查询在任一完成之前均已启动，不靠墙钟耗时猜测。真实模型并行隔离测试：`node --experimental-strip-types --import ./scripts/register-typescript.mjs backend/tests/model-parallel.ts`；不访问真实商品库或前端页面。

## 调用耗时与Token优化

对于全部节点均已提供invocation和expected的纯目录查询计划，直执行成功、预期参数匹配且nextOffset为null时，由程序完成节点核验，不再逐节点调用模型生成小结，保留一次最终汇总。分页未结束、查询失败、咨询附件或混合写任务继续原模型循环。权限、业务审核、模型额度和重试上限不变。

系统提示中的操作事实不再重复嵌入工具参数；工具调用消息仍保留完整参数和结果。计划摘要保留各节点目标、依赖和状态，只为活动节点附完整调用与预期，不重复已生成的小结。没有截断商品证据、压缩权限规则或删除会话历史。

隔离测量命令：`node --experimental-strip-types --import ./scripts/register-typescript.mjs backend/tests/model-performance.ts after`。脚本使用真实模型和测试商品，不写业务数据库；从响应usage统计Token，缺失时输出null，不拿字符数冒充Token。

本次同场景各一次前后测量，请求为“分别查询显卡目录价格和CPU目录价格。这是两个独立查询，互不依赖，不修改需求或配置。”：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 模型调用 | 4 | 2 |
| 输入Token | 41,502 | 20,333 |
| 输出Token | 1,018 | 835 |
| 总Token | 42,520 | 21,168 |
| 调用链耗时 | 16,373 ms | 13,666 ms |

本样本总Token降低约50.2%，耗时降低约16.5%。这不是跨场景平均、并发负载结果或统计显著性结论；模型输出长度、网络、服务端缓存及本机负载均可能影响测量。两次均验证两项任务完成且无写入。回归测试另验证分页、失败和写任务不能走快速完成路径；尚未进行真实数据库及页面端到端性能复测。

多轮消融对照使用 `node scripts/performance-suite.mjs`，固定五类场景、每组每类五次；详见 [评测方法](performance-evaluation.md)。原始样本及分场景成功率、平均 Token、耗时中位数与 P95 写入独立的 `reports/performance-时间戳/`。该对照仅关闭/开启查询快速完成与上下文去重，不代表历史版本，也不衡量 DAG 并行本身的收益。

复合请求例：查询显卡价格，同时将预算保存为9000元但暂不生成，应完成查询与需求保存，且不调用配置生成工具。若要求按新预算查询，查询节点依赖保存节点。

测试：`pnpm test` 包含图校验、失败传播、两次模型调用的简单路径、参数门禁、预期结果校验、重规划限制及多意图模拟调用链；真实模型隔离测试通过 `node --experimental-strip-types --import ./scripts/register-typescript.mjs backend/tests/model-execution-plan.ts` 显式运行，使用测试商品而非业务数据库，记录实际调用次数。结构校验不能证明模型没有漏提意图；真实模型测试也只证明所测输入的表现，不等于页面或真实数据库端到端验证。
