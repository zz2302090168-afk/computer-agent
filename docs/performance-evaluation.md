# 多轮性能对照

## 运行方式

在仓库根目录执行 `node scripts/performance-suite.mjs`。需要已有服务端模型配置；仅读取 `.env.local`，不修改配置。此命令会调用真实模型并产生费用，不纳入默认 `pnpm test`。

每次生成独立的 `reports/performance-时间戳/`，包括方法与代码指纹 `manifest.json`、逐次原始指标 `samples.jsonl`、运行期间代码一致性 `integrity.json`、分组指标 `summary.json` 与可阅读报告 `report.md`。不保存密钥、请求头或完整对话。测试商品来自固定夹具，不访问业务数据库；没有页面交互。

## 对照方法

- baseline：当前代码在评测子进程加载时，关闭纯多查询节点快速完成，并恢复事实参数与完整节点的重复提示。
- optimized：当前代码原样运行。
- 两组均保留当前规划、调度、并行、权限与业务审核。该对照只考察上述两项优化，是消融对照，不是历史版本回放，也不能用于衡量 DAG 或并行调度本身的收益。
- 5 类固定请求，每类每组 5 次，共 50 次。组别顺序交替，每次全新进程与会话，顺序发送，避免本地同时请求相互影响。
- 沿用生产调用参数：temperature=0.2、max_tokens=1600、流式响应；不为了得分修改提示或模型采样参数。模型名称见 manifest，服务端缓存与网络未受控。
- 单样本评测时限 60 秒，子进程保护时限 90 秒，均为测试保护，不改变生产超时。无预热；耗时从会话执行开始计至完成或异常，不含进程启动。

## 固定场景与通过条件

| 场景 | 主要断言 |
|---|---|
| 简单查询 | 查询 900 元以内显卡，预算保持 8000 元，无需求保存；固定目录中允许无匹配商品 |
| 独立多意图 | 显卡与 CPU 两项查询均成功，两节点完成，无需求保存 |
| 前后依赖 | 先将预算保存为 9000 元，查询显卡上限 900 元；图上有依赖，工具事实先保存后查询，不生成配置 |
| 分页 | 每次最多 2 条，模型收到的工具结果覆盖全部 8 张测试显卡，任务完成 |
| 查询失败 | 首次目录读取注入失败，仍有成功查询；两节点各有成功证据或明确阻断结果，不修改需求 |

每场景还检查最终答复非空与预算状态。失败场景“通过”代表正确处理注入失败，允许失败节点明确阻断，不代表全部查询成功恢复。自然语言答复的准确性、风格与事实完整性不由这些断言全面保证。

## 统计口径

成功率分母包含全部尝试，不剔除失败。平均调用数及耗时包含有测量值的失败样本；进程异常无可用指标时记 null，不冒充零。Token 使用实际响应 usage，任一调用缺少 usage 则整条请求记 null，并报告完整样本数；不按字符估计。

中位数与 P95 使用 nearest-rank。每场景仅 5 次，P95 等于最大值；混合总体每组 25 次，仅描述本固定测试集，不代表真实流量权重，也不是稳定线上 SLA。失败率上升或场景构成不同，不能单凭 Token 降低宣称优化有效。保留失败断言，不能测试后放宽标准美化结果。

运行完成会重新核对后端源码及评测脚本指纹；发生变化时保留原始记录但拒绝生成有效对照报告。修改夹具、模型配置或业务代码后应开启新批次，不混用旧样本。

## 2026-09-20 实测结果

完整数据见 [本批报告](../reports/performance-2026-09-20T04-35-55-055Z/report.md)。50 条记录均已核对唯一性、分组样本数、成功数、平均 Token 和分位数。

- 独立多意图查询：两组各 5/5 通过。基线调用为 4、6、4、6、5 次，平均 5 次；优化组均为 2 次。平均总 Token 54,436.6 → 21,214.2，降低 61.0%；耗时中位数 24,086 → 12,849 ms，降低 46.7%。这是此固定场景的五次消融对照，不是全产品平均。
- 全场景程序断言通过率：基线 19/25（76%），优化组 23/25（92%）。基线仅 23 条 usage 完整，优化组 25 条；不将整体 Token 均值直接包装成等成功任务的成本收益。
- 分页存在未解决问题：基线三次、优化组两次没有覆盖全部商品，但计划状态已标记完成；基线另有一次分页运行异常。观察结果支持“完成标记不能保证用户要求的全量分页目标”，尚未定位具体原因，本轮不修改生产逻辑。
- 另有基线简单查询一次、失败注入一次运行异常。记录只保留 `run_error`，不能据此断言是网络、模型服务或调度问题。
- 依赖场景两组各 5/5 通过，但中位耗时 17,111 → 17,585 ms，并未降低。不能宣称优化对每种任务都提速。

本轮 `pnpm test` 263 项通过，类型检查、评测文件代码检查与构建通过。没有真实数据库或前端端到端复测。采样期间源码指纹一致；采样结束后仅给评测脚本的目录枚举补充显式 UTF-8 与非 Dirent 返回选项以通过代码检查，不影响此次样本和统计。manifest 保留实际采样时指纹，未重写为修改后的值。
