# 动作声明阶段输入优化

2026-09-16。本轮只筛选一个有开销依据的候选，未重跑无收益的简短收尾/禁并行动作方案。

## 定位与改动

最近7轮现成记录包含24次模型请求，输入291,640 Token、输出4,537 Token，输入占98.5%。首次仅允许set_request_action时，系统消息仍约19,954字符，其中状态之前的通用业务说明约11,462字符，之后还包含执行阶段技能。

仅当可调用工具恰好只有set_request_action时，改用动作声明说明并逐字保留当前消息ID、需求、方案、探索状态和操作事实；用户消息、历史、工具定义不裁剪。动作后续执行仍传完整规则，16轮、重试及审核不变。非标准提示缺少明确状态边界时保留原文。模型跟踪记录实际压缩后的输入。

## 两轮成对对照

商品查询、空页联动续查、选择加会话补问3场景，每组重复2次；两轮交换控制/候选启动顺序。使用相同目录，真实模型与工具，无生产写入。

模型Token减少16.1%；没有观察到提速，总耗时反而高约4.9%，且两轮耗时方向不一致。这是小样本的用量收益，不是实际账单减少16.1%，也不证明全场景无回归。完整正文检查未发现新增错误商品、遗漏会话补问或未授权修改。目录正文重复在控制和候选中各出现一次，属于保留的现象，不计为优化收益。

另做8个真实模型的单次动作判断：知识、解释、只存需求、重新配机、危险售后停止、咨询人工入口、实际替换、缺需求澄清，动作及关键字段8/8符合预设。该探测不执行工具，不能代替完整业务端到端。
