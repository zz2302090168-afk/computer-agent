# Jev工具选择实验

## 范围

这不是入口意图路由。`JEV_TOOL_SELECTOR_ENABLED=true` 仅替换已有计划内、仍有未完成工作、多个可用候选、且不能直接执行时的工具选择。默认关闭，`.env.local` 不由代码修改。入口规划仍使用原模型；唯一工具且参数完整的直执行、已有并行读、纯文本收尾不额外调用Jev。

Jev收到当前活动节点、临时需求状态、已有工具事实及非system对话消息（包含实际工具结果），候选来自已有权限与状态过滤。选择结果必须属于本次候选、完整概率分布有效、选项概率至少0.9、Choice置信度至少0.8。这些是预先固定的实验门槛，不是正确率保证。

成功选择后，只把选中工具的Schema交给原模型，并要求调用工具；这一次原模型负责填参数，不再在多个候选中选工具。执行前额外校验工具名不可改选，原来的参数/权限/预算/兼容性/分页校验全部保留。Jev不能生成参数，也不能免除主模型填参调用。

Jev单次最长2秒、无自动重试；接口异常、未知选项或低置信度回退原模型选择。取消信号直接传播。回退会在toolSelections和诊断jev.tool_select记录原因，不能将回退后的请求称为完全由Jev选工具。没有更改已有主模型额度、重试或超时。

## 对照

运行 `node scripts/jev-comparison.mjs selector`，两组均关闭 `JEV_ROUTER_ENABLED`，只切换工具选择开关。固定四类场景：独立多查询（直执行控制组）、依赖查询、全量分页、首次目录失败。每类每组三次，交替AB/BA，共24次真实请求；测试目录不访问业务MySQL，不执行真实业务写入。

记录端到端耗时（包括Jev及回退）、LLM/Jev调用与Token、成功率、每次工具选择接受/回退状态。不同模型Token分别展示，不能简单当作相同成本。所有失败保留；usage缺失记null。原始记录和代码指纹位于独立reports目录，不和入口路由试验混合。

普通目录查询经常已经由入口给出完整参数，本来就没有独立工具选择调用。这类场景Jev调用为零是正常的，不应把墙钟差异解释为Jev收益。真实模型输出、网络和缓存未受控；每场景三次不足以证明稳定尾延迟。程序断言通过也不等于已人工评审所有自然语言输出。

额外进行一次带诊断日志的分页请求（不计入上述24条），同样超时。该次Jev选择了正确的search_catalog；主模型在单工具参数生成阶段遗漏offset/limit并新增过滤条件，程序校验拒绝后仍重复提交。证据指向本次参数生成/纠错链路退化，并不证明Jev选错工具，也不能断言全部超时具有相同原因。原有校验未放宽。

结论：本次实现没有取得收益，保留为默认关闭的实验开关，不修改.env.local，不推荐启用。以上是真实模型加固定测试目录的对照，不是业务MySQL或页面端到端验证，也不是全局性能结论。
