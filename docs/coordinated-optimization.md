# 协同测试与优化：本轮结论

2026-09-16。用户明确要求修复agent与主agent协作，并由orchestrator协调。主agent负责真实测试、独立状态断言和用量记录；修复agent负责必要业务与回归测试；协调agent审核方案、实际差异、完整答复和终态。

## 保留的局部修复

1. `select_plan` 在状态修改前核对当前用户明确序号及已有完整方案ID。第99套不存在时不能用有效第二套ID替代。真实ID含竖线，已用完整ID边界匹配覆盖，不能仅依据简短夹具ID验证。
2. 首次结构化动作声明可标注页面会话补充问题，完成正文追加准确的会话规则：目录往返保留且生成继续，刷新（包括目录页）、关闭和新会话清空。保留工具事实正文，避免恢复无依据的性能、库存或服务陈述。
3. 首版多编号一律澄清导致“不要第一套，选择第二套”未完成，失败已保留。后续仅对独立短分句、完整简单排除表达做对象约束提取，剩余唯一序号仍须存在且匹配。条件、比较、冲突及未覆盖表达不冒充通用语义解析。此校验不授予选择或确认权限。

没有更改预算、交付审核、超时、重试、候选回退或结束策略。`.env.local`未修改，目录只读，B0冻结不变。没有部署。

## 验证证据

固定用例 `eval/system/coordinated-quality.v2.json`。证据根目录 `eval/results/tuning-baseline-2026-09-16/`：

- `coordinated-core-a/b`：QUEUE01会话补答、QUEUE02无效编号、QUEUE03只解释，各两次，共6轮；状态和本轮目标语义经主agent与协调agent独立复核通过。
- `coordinated-adjacent-a/b`：正常选定、整单确认、先选后解释/查候选、合法长ID、明确否定，共9轮；8轮程序通过，COORD03首次误拒保留，不覆盖。
- `coordinated-reference-a/b`：受控排除修订后，QUEUE02/COORD03/COORD04各两次，共6轮程序通过；选定/确认状态核验正确。

本轮共21轮真实接口调用场景记录，不等于21次模型请求。程序共20/21通过，其中首次失败已定点修订复测。**不能据此称20/21完整任务成功**：部分答复仍有下述语义缺口。不同修订对应的backend源码全文及SHA-256在每次运行开始归档；不要混成同一版本成功率。

最终全套测试277/277通过，新增修复回归28/28；类型检查、代码检查、构建通过。真实接口基于冻结目录适配器，不等于实时数据库和浏览器端到端，本轮没有浏览器复测。

## 仍未解决

- 拒绝无效选定后的自由答复可能另列三套商品，漏标演示身份。最终QUEUE02两轮及COORD04其中一轮观察到，尽管状态正确，也不算全文质量通过。下一步宜从失败工具输出提供结构化事实和简短拒绝正文，而非助手关键词过滤。
- TAIL02“只查更便宜”仍包含同价或更贵候选。这是已有过滤/答复缺口，程序仅检查只读查询并不足够，需单独处理。
- 任意自由复合问答、未知自然语言ID和通用条件作用域未全面解决。

## 耗时与费用

汇总 `coordinated-final-metrics.json` 分开记录模型和Embedding的输入/输出/总Token、带用量记录的调用数、各题耗时和失败，不删除失败费用。没有返回用量的请求不假装为零，接口金额缺实际计价依据。

核心三题：旧版本9次有用量的模型调用/104,091模型Token；修复两轮各9次，分别105,518和104,796模型Token，各轮另有10,373 Embedding Token。旧版本有已确认质量失败，不能把与旧版本的耗时或Token差异包装成同质量收益。部分解释工具出现重复调用，留作后续性能诊断。本轮没有采用新的性能优化。

## 决策

保留对象校验和会话补答的局部修复；全面验收未过。团队按“修复agent改动→主agent真实对照→协调agent独立验收”的方式继续后续迭代。下一轮先处理拒绝答复与更便宜过滤，再评估重复调用；不能为节省调用漏做任务。
