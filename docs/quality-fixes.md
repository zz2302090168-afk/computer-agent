# 质量与规则修复记录

后续完整基线、换件答复和浏览器复测见 [基线复测与换件答复修复](./baseline-regression.md)。以下保留本次修复时的记录。

2026-09-15。本轮承接全链路试跑的已观察失败，只处理目录查询、售后动作和回答事实。

## 改了什么

1. **目录查询**：在动作选择上下文中明确“浏览目录”不继承已有配置的预算、兼容或替换范围。价格参数允许 `null` 表示未指定；真实调用又发现模型将 `1500`、`0` 序列化为字符串，因此只对无歧义十进制价格做等值转换。明确0元仍为0元，不自动放宽条件；自然语言价格、空串、指数和非有限数仍拒绝。
2. **售后动作**：依据本轮已声明的结构化动作，收窄 `update_support.action` 的可选值；每次克隆工具定义，不串到其他会话。执行端独立验证仍保留，报错明确显示已声明动作和本次动作。主题参数直接列出知识库现有中文主题名；动作选择先判断是否已达到停止条件。
3. **回答事实**：推荐结果、配置解释和评估由实际业务工具生成最终文本，保留报价、型号、演示身份、具体待核对项和建议。价格占比实际计算，不把排序权重当成价格占比；便宜不表述为性能相同。模型编造的收尾内容不交付、不流式显示。其他自由问答仍由模型生成，不宣称所有事实错误已经消除。

没有增加独立审核模型，没有改变预算/兼容算法、超时、重试、候选额度或停止后的授权边界。没有修改 `.env.local`。未部署。

## 修改中的失败与处理

- 只补提示时，1500元与0元被模型传成字符串，导致拒绝和重复失败。按实际证据在价格入口做等值归一化后复测通过，没有接受模糊价格。
- “首次报告使用continue”这句新增提示过于笼统。在一次唯一数据且硬盘反复掉线场景中，状态未停止。已删除该提示；原错误结果保留，随后加强动作说明中的停止优先级并补相邻案例。
- 没有中文主题说明时，音频在重复测试中仍选错。当前使用知识库自身的主题名称，不另造主题或根据助手回复匹配意图。
- 推荐/解释/评估的提示约束不足以消除无证据断言，改为工具事实正文。两条旧测试只比较模型收尾套话，现改为核验真实报价、演示身份和待核对提示；实际生成、保存、审核、调用次数与授权断言均保留。

## 验证及实际边界

- 全套程序测试246/246通过，含价格null/0/字符串边界、动作隔离及越权拒绝、模型编造内容不进入最终答复和流式输出。
- 类型检查、代码检查、生产构建通过。
- 真实模型复测保留每次运行，失败未被重跑覆盖。目录1500元上限、明确0元和只查硬盘替换候选在 `quality-adjacent-r2` 为3/3程序通过；不设价格上限的AMD目录在后续 `quality-final` 也通过独立目录核对。
- 推荐、解释、评估的真实答复已经读取核对：演示身份正确显示，主板价格占比从错误的9%改为实际18.1%，评估不再宣称降价后性能相同。
- 售后动作、恢复系统、音频和危险停止最终结果见 `quality-safety-r4`；扩展的唯一数据风险、已有备份、耳机、麦克风、屏幕无信号、人工入口咨询见 `quality-boundaries`。程序通过不替代语义人工验收。
- 本轮没有重新执行真实页面旅程，也没有完成全量独立测试集、质量消融或速度费用对照；不宣称端到端全部正常或总体性能提升。
