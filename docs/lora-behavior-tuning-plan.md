# LoRA行为微调方案（设计，尚未训练）

2026-09-16。目标是降低错误工具选择、错误参数、无证据扩写与重复调用；知识正文仍由RAG提供，商品、价格和规则仍由数据库及程序决定。LoRA是候选优化，不能保证消除错误，也不替代运行时审核。

## 先决条件

- 当前使用托管模型接口。是否支持该模型的微调任务或加载LoRA适配器尚未核验，不能把本地适配器直接当作现有API可用参数。
- 可选路径：服务商明确支持的训练与部署能力；或获得可训练权重的模型及配套推理服务。确定准确模型版本、工具调用模板、许可证、显存、训练与服务预算后再执行。
- 更换基座时必须先测未微调版本；不能把基座变更带来的差异算作LoRA收益。当前接口与`.env.local`不改动。

## 数据设计

先试制约300至500条经过复核的训练轨迹；这只是首轮规模建议，不是充分性保证。当前少量失败题不足以支持可靠微调结论。

| 训练任务 | 必须覆盖的正例与边界 |
| --- | --- |
| 路由 | 解释名称→知识；解释现有方案选型→配置解释；浏览目录→搜索；只读替换预览→替换查询；复合请求与纯问答分开 |
| 参数 | 芯片厂商/板卡品牌/完整型号；双语品牌；先查真实商品ID；联动换件不能漏掉指定硬盘；不把旧配件身份当成用户新约束；歧义多匹配不猜第一条；明确品牌条件不取消；同价不算更便宜 |
| 证据回答 | 本轮有效知识ID；完整限定与否定；未覆盖用partial/unsupported；未检索或历史ID不能作为依据；不扩写厂商合作/制造/性能 |
| 多轮与失败 | 先失败后修正；检索故障；已选方案与仅解释；查询不修改；取消约束；不重复工具；售后与配置相邻边界 |

从真实失败中提取输入，人工修订并复核正确工具轨迹，再经程序回放核验。失败输出保留为评测证据，不能直接作为SFT正确答案；模型自评通过不等于标签正确。移除密钥、认证字段及不必要的个人信息，保留同一示例内消息ID、商品ID和工具结果的对应关系。

每例保存`messages`（含assistant的tool_calls、tool结果）和`tools`的JSON Schema。训练目标放在正确的assistant动作、参数与证据选择；工具结果作为上下文，不让模型学习生成伪造的工具证据。检查模板的assistant loss mask确实覆盖工具调用，不能静默漏训。根据真实长度选择上下文上限，不能截掉商品证据、用户约束或目标调用。

训练/验证/最终测试按对话、模板家族和商品型号家族分组隔离；同一句改写不得跨集合。GPU-KNOW01/02、PRICE07已经参与调试，只能作开发回归，不能再包装成未见最终测试。最终集另建并冻结，加入训练未出现的别名、型号与复合表达。

## 实验顺序

1. 固定修复后的工具契约、知识版本、目录与规则，记录当前API基线。
2. 选择训练底座，先评测同一底座未微调版本。
3. 用工具调用SFT训练一份LoRA。可从rank=8、alpha=16、dropout=0.05、学习率1e-4、1个epoch做小试，具体值须依据模型、数据长度和验证表现调整；这些不是已验证配置。不先展开大规模参数网格。
4. 比较同一底座“无LoRA”与“有LoRA”；工具、知识、目录、采样和测试集保持一致。仅在验证集选择训练轮次，最终集最后使用。
5. 有明确收益后再消融：只训练路由、路由加参数、再加入证据选择，确认哪个部分带来收益。

采用TRL的工具调用SFT和PEFT LoRA是一条可行实现路线，工具调用样本须包含工具消息与Schema，适配器方案须匹配所选模型。[TRL工具调用训练](https://huggingface.co/docs/trl/sft_trainer#tool-calling-with-sft)、[TRL与PEFT集成](https://huggingface.co/docs/trl/en/peft_integration)。

## 采用标准

- 首要：完整任务成功率、工具选择、参数有效性、证据支持程度、用户规则与状态正确性；程序检查和全文复核分别报告。
- 不接受新增越权修改、预算/品牌限制绕过或无证据事实，即使平均分上升。
- 建议首轮筛选目标为主要错误数相对未微调同底座减少至少30%，且其他类别无可观察退步；这是实验目标，不是收益承诺。报告样本量、各类计数与重复结果，不用小样本声称统计显著。
- 同时记录模型轮次、重复调用、输入/输出Token、延迟，以及训练、部署和推理实际成本。微调本身不保证更快或更便宜。
- 无稳定收益则不切换。保留RAG和程序审核，LoRA仅作为改善模型行为的一层。
