# 当前阶段目标与验收

2026-09-16，用户要求先固定goal再自动继续。质量优先，耗时和费用次之。此目标不是整个项目的最终验收。

## 目标

1. 拒绝无效方案选择时，使用真实失败依据，不自行列出未标演示身份的商品；选定/确认状态保持，后续成功结果不得被旧拒绝覆盖。
2. “只查更便宜”严格过滤同价和涨价；单件按原件价格、联动整体降价按替换总额。保持统一审核、原过滤和分页含义，明确取消价格限制必须生效。
3. 两项核心问题各至少两次真实接口复测，覆盖合法选择/确认、解释、替换查询、无候选、分页及取消约束。检查完整正文和状态，不能将程序通过当完整质量通过。
4. 质量门槛通过后最多比较两个独立性能候选。保持完整任务质量，筛选目标：耗时约20%下降或Token约15%下降。无胜出方案时保留基线也是合格的实验结论，不承诺一定改善。
5. 相关回归、类型检查、代码检查、构建通过；核心规则变更运行完整测试。协调agent独立审核实际差异与证据，最终给短结论、可追溯记录和限制。

## 分工与执行顺序

- 修复agent：必要backend改动和相关单测，源码稳定后通知冻结。
- 主agent：eval与文档、独立判定、真实调用、性能对照及最终源码核验。
- 协调agent：审设计、调度、独立阅读差异/答复/终态；不能仅转述完成声明。

先修复并小规模实测，再补足相邻场景；新回归先收敛，不靠放宽期望通过。质量尚未通过不得采用提前结束等省调用改动。模型实测最多两个进程，不增加重试/超时；失败和费用全部保留。

## 冻结及判定

修复前C3工作区源文件已冻结在 `eval/results/goal-quality-performance-2026-09-16/baseline-source/`，manifest含326个文件指纹与Git HEAD，包含未提交工作。B0仍保留。商品与显示器沿用只读快照，未改 `.env.local`。

用例 `eval/system/goal-quality.v1.json`。价格差额由评测代码依据真实商品ID与冻结价格独立计算；同价/高价、分页重复、超页大小、取消限制未生效分别记录。PRICE06的9700X已核验目录仅一条2100元记录，严格同型号更便宜预期为空有依据。

语义正文由主agent与协调agent分别检查，明确非人工真值。金额无账户实际单价时只报模型和Embedding用量；带用量的调用不冒充所有失败请求次数。不写生产数据库、不改变页面会话约定、不绕过授权和审核。

## 停止条件

本阶段通过上述质量门槛，完成最多两项性能筛选并保留胜出或基线，检查与独立验收齐全后结束goal。未覆盖的完整80开发/40验证/40最终测试、浏览器故障矩阵和消融必须如实说明，不因本阶段完成宣称全项目完成。

## 执行中的边界复核

两个原始核心问题的局部验收已通过，但新增联动场景发现两个缺口：PRICE05首个原始分页没有审核合格候选，PRICE07型号与品牌拆分错误导致漏检真实存在的组合。PRICE07五次真实失败全部保留，整个无效的字段说明尝试已撤回，不继续堆叠提示或放宽检查。
