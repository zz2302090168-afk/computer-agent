# 选定方案的 LLM 调用优化

## 改动

动作声明允许同时提出 `selectPlan` 参数。单个动作声明成功后，下一轮通过原 `select_plan` 工具执行，省去单独生成选定参数的一次模型请求。不提供参数时保留原流程，多工具响应不再追加自动选定。

参数提案不等于成功选定：工具权限、用户消息引用、方案编号、最新目录和交付审核仍由原调用链核验。失败返回给模型处理；选定后仍请求模型检查解释、换件查询等剩余工作。不提前结束，不调整 16 轮上限、超时或重试次数。

仅优化已有方案的选定/确认，未推广到新配置生成、替换或目录检索。动作工具增加一个可选字段，其他请求的首轮输入会略有增加。

## 2026-09-16 实测

真实模型 qwen3.5-flash，冻结目录快照、内存会话，无数据库写入。相同 QUEUE01 请求为“选第二套，不确认，再问刷新能否恢复”。第二轮反转测试顺序。

| 指标（两轮合计） | 原流程 | 合并参数 |
| --- | ---: | ---: |
| 模型调用 | 6 | 4 |
| 总模型 Token | 64,280 | 38,676 |
| 耗时 | 21.48 秒 | 20.32 秒 |

Token 减少 39.8%；耗时减少 5.4%，但第一轮略慢、第二轮较快，样本不足以证明稳定提速，也未核对实际费用。两组最终答复均保留选定事实、未确认购买及会话清空规则。

控制 A 在修改前运行；控制 B 使用 `EVAL_PERFORMANCE_CANDIDATE=unfused-selection` 隐去新增工具字段，仍使用已有动作上下文压缩。此开关只用于评测。

另外 7 轮真实模型边界测试通过：整单确认、先选定后跨轮确认、选定后解释、选定后查询候选、不存在的第 99 套、明确禁止选定时只解释。检查了最终答复、调用事实及状态；未将脚本的程序通过标记视为自动语义审查通过。

程序测试 355/355，通过类型检查、lint 和构建。新增测试覆盖减少调用、复合解释、会话补问、错误编号拦截、其他动作不能附带选定权限。未做浏览器或生产数据库端到端测试，未部署。
