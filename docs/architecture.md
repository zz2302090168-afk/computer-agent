# 第一版架构

网页由 Sites 的 Vinext / React 承载，后端使用 TypeScript，数据库为 D1（SQLite）。与前期 Python 草案不同，实际统一使用 TypeScript，以便网页与服务端一起运行与部署。

## 目录

| 目录 | 职责 |
| --- | --- |
| app | 页面入口、HTTP 路由、全局样式 |
| frontend | 用户需求、方案、配件替换和目录界面 |
| backend/agent | 需求提取、可选模型解释 |
| backend/domain | 商品、需求、方案类型 |
| backend/rules | 预算及兼容性硬约束 |
| backend/services | DIY 搜索、整机排序、配件替换 |
| backend/tools | 商品查询、报价、校验、检索工具 |
| backend/rag | 中文双字词与关键词检索 |
| backend/performance | 同条件 FPS 证据匹配 |
| backend/db | 数据库查询与初始化 |
| db、drizzle | 数据库声明、可追踪迁移 |
| data | 商品目录 JSON 与性能数据约定 |
| knowledge | 知识源与可阅读的分类文档 |
| skills | 两种推荐流程 |
| scripts | 数据导出、导入准备、单元与接口检查 |

## 执行顺序

结构化表单及自然语言补充 → 服务端需求校验 → 数据库目录 → 知识检索 → 有界候选搜索 / 整机筛选 → 预算和兼容性检查 → 可选模型解释 → 会话保存 → 界面展示。

每次替换通过商品 ID 重新读取目录并计算，客户端传入的总价不可信。会话使用 HttpOnly Cookie 和独立随机 ID，无用户传入 sessionId。商品没有数量或在售状态；整机 partIds 表示安装清单。

## 第一版明确边界

- 商品为合成演示目录，品牌星构 DEMO，DEMO-A/B 是演示平台，不可按此购买真实配件。
- 知识中厂家事实与项目策略分开标注；功耗余量与用途权重是演示策略，不是统一硬件标准。
- 知识检索采用可运行的词法索引，未使用 embedding。配置模型后将检索片段送入解释，形成检索增强生成；未配置时展示检索和规则解释。
- 模型只解释已校验方案，不拥有价格或兼容性决定权。需提供模型服务配置后才能实测模型效果。
- 需求提取是有限规则，不支持任意复杂自然语言；优先使用结构化控件。企业阶段再加入结构化模型提取和更完整追问状态机。
- 有界搜索不保证穷尽所有组合；无结果表示当前检索候选无可用方案，不能证明完整目录数学上无解。
- 当前不提供真实 FPS 数值。估算器先实现严格匹配，近似配置预测未校准。
- 显示器阶段在主机确认后提示，具体商品推荐待补充显示器目录。
- 商家目录通过文件导入更新，尚无带权限控制的后台管理页面。
- WebMCP 是可选浏览器能力，非后端 MCP 服务。无支持的浏览器测试上下文，未实测注册调用；不影响普通网页使用。
