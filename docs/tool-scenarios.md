# 工具能力场景

本轮先编写可执行场景，再补工具。自动化测试使用标注为demo的隔离夹具，不访问真实模型或写入商品数据库。自然语言示例用于说明用户意图，测试直接调用结构化工具，不等同于真实模型意图识别验收。

| 场景    | 用户示例                         | 应有能力与验收                                                                    |
| ------- | -------------------------------- | --------------------------------------------------------------------------------- |
| S01–S04 | 就要均衡这套／确认高价这套       | select_plan持久化具体方案；选择与确认分开；无效ID、其他消息或报价变化不能修改状态 |
| S05     | 把显卡换一下                     | 未选定且有多套时返回可选方案，不猜第一套                                          |
| S06     | CPU等其他配件不动，找能换的显卡  | find_replacements只检查固定其余七件的组合，按当前误差校验价格并返回冲突           |
| S07     | 看看白色显卡能否替换             | 预览只标明该类别颜色变化，不修改任务、不推广为全白                                |
| S08     | 有没有某型号？没有就查别的       | 空过滤结果与类别商品总数分开，允许继续查询                                        |
| S09     | 恢复任务后问：这套为什么选这个？ | 从保存的选定状态找到方案；解释和查询不写状态                                      |
| S10     | 替换失败，换个候选继续           | 保留旧方案，允许重试；成功仅改指定件，旧确认失效                                  |
| S11     | 整机换一个显卡                   | 明确商家整机不可拆件，不悄悄改成DIY                                               |
| S12     | 还没配机就要求选择或替换         | 返回缺少配置，不凭空生成                                                          |

S13–S18补充：分页首屏无可用项、方案变化后的失败缓存、参考不可确认、保存冲突无半更新、多套解释与评估不猜对象、两件联动替换保持其余六件。

S19–S21：两件联动候选整体审核且查询不写状态、组合分页不冒充全局搜索、重复类别和混用参数拒绝。单件查询保留原接口，多件查询使用items数组；两者复用同一整体审核路径。

S22–S23：同方案跨轮新增替换类别时继承最近查询的原类别过滤条件，明确清空时取消过滤，其他方案不继承；查询参数纠正成功后清除上一失败的阻塞状态。

M01连续六轮真实模型对话：选定均衡方案→只查名称含“星云”的演示显卡（电源不足）→允许电源一起换、查询两组→用上一轮第二组替换→解释且不确认→最终确认。每轮传回完整聊天历史和最新任务状态，消息经过JSON序列化再恢复，不预设模型工具调用；检查预算延续、预览不写配置、查询事实随历史保存、跨轮指代选择正确、其余六件不变和最终确认边界。该测试使用隔离演示目录与内存保存，不覆盖真实数据库和浏览器。可用`pnpm test:model --multi`只运行此连续场景。
